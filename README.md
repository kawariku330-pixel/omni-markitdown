# omni-markitdown `v1.1.1`

PDF・Word・Excel・スキャン文書を、AI に読ませやすい Markdown に変換するツール。
**日本語の文書**（論文・報告書・書籍のスキャンなど）を、段組・縦書き・注釈・脚注まで崩さずに変換することを重視している。

- **注釈・コメントを捨てずに、該当する段落のすぐ下に置く**: Word のコメント・脚注、PDF のハイライト・付箋・返信・手書きの書き込みを、どの文に付いていたかが分かる位置に残す（[下で詳しく](#注釈とコメントの扱い--このツールの特徴)）。
- **すべてパソコンの中で動く**: 変換・OCR とも外部のサービスに送らない（ネット接続はインストールのときだけ）。社外に出せない資料にも使える。
- **スキャンも読める**: 国立国会図書館の OCR「NDLOCR-Lite」をモデルごと同封。縦書き・2 段組も読み順どおりに並べる。
- **OCR の読み違いを見つけやすい**: 原本ページへのリンクと、金額・日付・番号の照合リストを出す。

## 注釈とコメントの扱い — このツールの特徴

文書を Markdown にするツールの多くは、本文だけを取り出す。PDF の注釈（ハイライト・付箋）や Word のコメントは捨てるか、文書の最後にまとめて出すことが多く、**「誰が、どの文に、何を書いたか」が失われる**。読み込んだ資料について AI に質問したり、校閲や確認の経過を引き継いだりするときに、この情報が欠けるのは痛い。

omni-markitdown は、注釈・コメント・脚注を**対象の段落のすぐ下に引用として差し込む**。

```markdown
本調査は，対象地域における交通量の変化を調べたものである。

> 🖍️ ハイライト [作成者A]: 「交通量の変化」 — ここが論点

> 💬 コメント [作成者A]: 数字の出典を確認
>
>   ↳ 返信 [作成者B]: 資料12頁です

> 📝 脚注 [^1]: 総務省統計（令和元年）参照。
```

| 元の文書 | 何を残すか |
|---|---|
| Word のコメント | 作成者と内容。コメントが付いた段落の直後 |
| Word の脚注・文末脚注 | 本文に `[^1]` の印、段落の直後に脚注の中身 |
| PDF のハイライト・下線・波線・取り消し線 | **線を引いた文字だけ**（2 行にまたがっても前後の文は入らない）と、付けたコメント |
| PDF の付箋（コメント） | 作成者と内容。**返信はスレッドのまま**（`↳ 返信`）元のコメントの下にまとめる |
| PDF の丸・四角の囲み | 囲まれた文字 |
| PDF に直接打ち込んだ文字（フリーテキスト） | `📝 書き込み` として 1 回だけ。本文には混ぜない |
| PDF の手書きの線・スタンプ | 文章が無くても「あった」ことを残す |

- 注釈は、重なっている段落（余白の付箋なら縦に最も近い段落）の直後に置く。
- `result.notes` からは、種類・作成者・ページ番号つきの一覧としても取り出せる。
- 不要なら `--no-notes` で出さない（そのときフリーテキストは本文の文字として残す）。

## 対応している形式

| 形式 | 拡張子 | 主にできること |
|---|---|---|
| PDF（文字あり） | `.pdf` | 段組の読み順、見出し、罫線表、画像、ヘッダー・ページ番号の除去、注釈（ハイライト・コメント・返信） |
| PDF（スキャン） | `.pdf` | OCR（自動判定）、原本ページへのリンク、照合リスト |
| 画像 | `.png` `.jpg` `.jpeg` `.tif` `.tiff` `.bmp` `.webp` | OCR |
| Word | `.docx` | 見出し、太字・斜体・リンク、箇条書き・番号付きリスト、表（結合セル）、画像、脚注・文末脚注・コメント |
| Excel / PowerPoint / その他 | `.xlsx` `.xls` `.pptx` `.csv` `.html` `.htm` `.epub` `.json` `.xml` `.zip` | Microsoft MarkItDown で変換 |
| 音声 | `.mp3` `.wav` `.m4a` `.aac` `.flac` `.ogg` `.wma` | 再生時間などの情報、ローカル文字起こし（`--transcribe`） |
| テキスト | `.txt` `.md` など | そのまま（Shift_JIS も自動判定） |

`.doc`（古い Word）と `.ppt`（古い PowerPoint）は読めない（「対応していない形式です」というエラーになる）。Word / PowerPoint で `.docx` / `.pptx` に保存し直してから変換する。

## インストール

Python 3.11 以上が必要。

```bash
git clone https://github.com/kawariku330-pixel/omni-markitdown.git
cd omni-markitdown
pip install -e ".[ocr]"
```

| コマンド | 入るもの |
|---|---|
| `pip install -e .` | OCR 以外のすべて（スキャンページは画像リンクと警告だけを出す） |
| `pip install -e ".[ocr]"` | ＋ 同封 OCR を動かす部品（opencv など）。**通常はこれを推奨** |
| `pip install -e ".[audio]"` | ＋ 音声の文字起こし（faster-whisper） |
| `pip install -e ".[all]"` | すべて |

- `.[ocr]` の opencv は、本体の numpy を 2.x に上げてしまわない版（4.12 未満）に絞っている。
- OCR のモデル（約 150MB）はリポジトリに入っているので、別にダウンロードするものはない。
- 更新は `git pull` だけでよい（依存が増えたときは `pip install -e ".[ocr]"` をもう一度）。
- Windows で深いフォルダ（OneDrive の下など）に置いて、パスが 260 文字を超えても同封 OCR は動く。
- 版ごとの変更は [リリース一覧](https://github.com/kawariku330-pixel/omni-markitdown/releases) と下の「変更履歴」。

## 使い方

### コマンド

```bash
# 1 ファイル（出力先を省くと同じ場所に .md を作る）
omni-markitdown 報告書.pdf -o 報告書.md

# フォルダごと（中の対応ファイルをすべて変換。サブフォルダも同じ構成で出力）
omni-markitdown ./資料 -o ./資料_md

# 全ページを OCR する（文字の層が壊れている・信用できない PDF 向け）
omni-markitdown 古い資料.pdf -o 古い資料.md --ocr
```

| オプション | 意味 |
|---|---|
| `-o, --output` | 出力先（入力がフォルダなら出力先フォルダ） |
| `--ocr` | 全ページを OCR する（OCR が使えなければエラー） |
| `--no-images` | 画像を保存しない |
| `--no-notes` | 脚注・コメント・注釈を出さない |
| `--assets-dir` | 画像の保存先フォルダ名（既定 `_assets`） |
| `--transcribe` | 音声を文字起こしする |
| `--ndlocr-cmd` | 別に入れた ndlocr-lite を使うときのコマンド |

- 入力が `.md` のときは `名前.converted.md` に出し、**原本は上書きしない**。
- OCR のように時間のかかる処理は「⏳ OCR 16 / 250 ページ」のように進み具合を表示する。

### 出力されるもの

```
報告書.md               本文
_assets/                画像（図・写真、OCR したページの原本画像）
報告書.ocr_check.md     OCR の照合リスト（OCR したページに数字があるときだけ）
```

### 出力の例

```markdown
# 第1章 概要

本調査は，対象地域における交通量の変化を調べたものである。…

> 🖍️ ハイライト [作成者A]: 「交通量の変化」 — ここが論点

> 💬 コメント [作成者A]: 数字の出典を確認
>
>   ↳ 返信 [作成者B]: 資料12頁です

| 項目 | 金額 |
| --- | --- |
| 予算 | 100万円 |
```

## PDF の読み取り

### 文字の入った PDF

PyMuPDF で文字 1 つ 1 つの座標を取り、行と段落を組み立て直している。官公庁の PDF などでよくある次の崩れに対応している。

- 読点「，」だけが後から重ね打ちされ、行の外に浮く
- 1 行ずつ別のまとまりになっていて、段落としてつながらない
- 太字を「同じ文字を少しずらして 2 回描く」方法で表している
- 傍点（強調の点）が本文に混ざる
- 漢字が康熙部首という別の文字コードに化ける（⾒→見）
- 2 段組・3 段組（左の段を読み切ってから右の段へ）

あわせて、文字サイズによる見出し（`#` `##` `###`）、罫線のある表、ヘッダー・フッター・ページ番号の除去、画像の位置への埋め込み（同じ画像は 1 回だけ保存）を行う。

公開されている官公庁の PDF（複数年度・複数分野）で、手作業で整えた版と文単位で 99〜100% 一致した。

### 注釈の出力形式

考え方と全体像は「[注釈とコメントの扱い](#注釈とコメントの扱い--このツールの特徴)」を参照。PDF の注釈は次の形で出す。

| 注釈 | 出力 |
|---|---|
| ハイライト・下線・波線・取り消し線 | `> 🖍️ ハイライト [作成者]: 「線を引いた文字だけ」 — コメント` |
| 付箋（コメント） | `> 💬 コメント [作成者]: …`。返信は下に `↳ 返信` でまとめる |
| 四角・丸の囲み | `> ⭕ 囲み（丸）: 「囲まれた文字」` |
| ページに打ち込んだ文字（フリーテキスト） | `> 📝 書き込み: …`（本文には混ぜない） |
| 手書きの線・スタンプ | `> ✍️ 手書きの書き込み`（文章が無くても「あった」ことを残す） |

`--no-notes` のときは注釈を出さず、フリーテキストは本文の文字として残す。

## OCR（スキャン文書）

### いつ OCR するか

- 文字がほとんど無いページ（スキャン）と、文字の層が壊れているページ（前の OCR の失敗などで制御文字だらけ）は**自動で OCR** する。
- `--ocr` を付けると全ページを OCR する。
- 同封の OCR が使えないときは、OCR せずに画像へのリンクと「OCR エンジンが無いため読み取っていません」という警告を出す（偽の文字は出さない）。

### 読み取ったあとの整え方

- 読み順は NDLOCR-Lite が付ける順番（縦書きは右の列から、2 段組は左の段から）に従う。
- 欄外の書名・章名（柱）、ページ番号、ルビは捨てる。見出しは `##` にする。
- 半角で読まれた「,」「.」「( )」を、日本語の文中では「，」「（ ）」に戻す。句読点の直後に入った余計な空白（「担当、 その他」）は取る（英文の空白は残す）。漢数字の〇を記号の「○」で読んだもの（「二○条」）は「二〇条」に戻す。
- 段やページの境目で切れた文はつなぎ直す。半分以上のページに出る短い行（透かし・柱）は取り除く。

### 精度と照合

文字の入った PDF をわざと画像にして OCR し、元の文字と比べた実測:

| 項目 | 結果 |
|---|---|
| 文字の誤り率 | 約 0.4%（約 250 文字に 1 文字） |
| 算用数字の金額・日付・番号 | 70 個中 70 個が正確 |
| 速さ | 1 ページ約 5 秒（250 ページの本で約 20 分） |

読み違えは、似た字（論拠→贅拠、法的→法約）、記号（(ア)→(7)）、**同じ字が続く漢数字（四〇〇〇円→四〇〇〇〇円）**、白抜き数字の見出しに偏る。文章の意味からは正誤を判断できないので、**引用・転記する数字は必ず原本と照らし合わせる**。そのために次の 2 つを出す。

- **原本ページへのリンク**: OCR したページの先頭に `[📄 原本 p.12](_assets/page_p012_….jpg)`。クリックすると元のページの画像が開く。
- **照合リスト（`名前.ocr_check.md`）**: 金額・日付・条番号・文献の巻号頁・番号を、ページ番号と前後の文つきで一覧にする。同じ字が続く読み違えやすい値には ⚠ を付ける。本文とは別のファイルなので、AI に読ませる本文は汚れない。

```markdown
| ページ | 種類 | 読み取り値 | 前後の文 | 確認 |
| --- | --- | --- | --- | --- |
| 2 | 金額 | ⚠ 四〇〇〇〇円 | 、委託先に支払った四〇〇〇〇円は作業に対する報酬の | ☐ |
```

### 解像度

OCR はページを 200dpi の画像にして読む（`pdf_ocr_dpi`）。NDLOCR-Lite は画像を縮めて読むため、細かくしても精度は上がらず、実測では 320dpi で誤りが増えた（150dpi 0.38% / 200dpi 0.40% / 320dpi 1.37%）。

## Python から使う

```python
from omni_markitdown import convert, ConversionConfig, OmniConverter

# 変換して保存（照合リストもこのとき書き出す）
result = convert("報告書.pdf", "out/報告書.md")
print(result.markdown)
print(result.metadata.get("ocr_pages"))  # OCR したページ（PDF のとき）
print(result.metadata.get("warnings"))   # 警告

# 設定を変える
config = ConversionConfig(enable_ocr=True, extract_images=False)
result = OmniConverter(config).convert("古い資料.pdf", output_dir="out")
```

主な設定（`ConversionConfig`）:

| 設定 | 既定 | 意味 |
|---|---|---|
| `extract_images` | `True` | 画像を `_assets/` に保存する |
| `extract_notes` | `True` | 脚注・コメント・注釈を出す |
| `enable_ocr` | `False` | 全ページを OCR する |
| `auto_ocr` | `True` | スキャンページ・壊れた文字の層を自動で OCR する |
| `pdf_ocr_dpi` | `200` | OCR に渡す画像の解像度 |
| `ocr_page_links` | `True` | OCR したページに原本ページ画像へのリンクを置く |
| `ocr_check_list` | `True` | 照合リストを書き出す（`convert()` で出力先を指定したとき） |
| `ndlocr_command` | `None` | 別に入れた ndlocr-lite を使うときのコマンド |
| `assets_dir` | `"_assets"` | 画像の保存先フォルダ名 |
| `max_file_size_mb` | `100` | これより大きいファイルは変換しない |

`result` には `markdown`（本文）、`assets`（保存した画像）、`notes`（脚注・コメント・注釈）、`metadata`（ページ数・OCR したページ・警告・照合リストの項目など）が入る。

## 既知の限界

- OCR の読み違いはゼロにならない（上の「精度と照合」）。特に白抜き数字の見出し（「22,」「J」のように崩れる）と、同じ字が続く漢数字。
- 縦書きで文字の層がある PDF は、行を組み立て直さず元の行のまま扱う（未検証）。縦書きのスキャンは OCR で読める。
- 罫線の無い表は表として認識せず、本文として出す。
- 白黒反転・手書きの文字・ひどく傾いたスキャンは OCR の精度が落ちる。

## 変更履歴

### v1.1.1 (2026-11-03)
- OCR が「、」「。」の直後に入れる空白（200dpi で読むと出る）を取り除くようにした。
- 「//」「ii」「ll」のような幅の狭い同じ文字の並びを、太字の重ね描きと間違えて 1 つ消していたのを直した（URL などで発生）。
- Windows で深いフォルダに置き、モデルのパスが 260 文字を超えると同封 OCR が止まっていたのを直した。
- 文字の層があるのに文字数が少ないページ（章の扉など）を「スキャン」と判定して OCR し、正しい文字を上書きしていたのを直した。スキャンと見なすのは、文字が無いページか、文字が少なくページの大半を画像（または図形で描いた文字）が占めるページだけにした。
- `.doc` / `.ppt` など対応していないバイナリを、意味のない文字のまま「変換成功」にしていたのをエラーにした。
- PDF の注釈を、対象の段落の直後に置くようにした（以前はページの最後にまとめていた）。
- 2 行にまたがるハイライトで、線を引いていない前後の文まで取り込んでいたのを直した。
- ページに打ち込んだ文字（フリーテキスト）が本文に混ざって二重に出ていたのを直した。
- コメントへの返信をスレッドでまとめ、手書きの線・スタンプ・囲みも残すようにした。
- OCR の解像度を、元のスキャンに合わせて上げず、常に 200dpi にした（高解像度で誤りが増えたため）。

- PDF: 文字単位の行組み立て、段組の読み順、見出し、罫線表、ヘッダー・ページ番号の除去、画像の位置埋め込み・重複排除。
- Word: 太字・斜体・リンク・リスト・画像・文末脚注・結合セル。
- コマンド: フォルダ一括変換、`.md` 原本の上書き防止、Shift_JIS テキスト。MCP: `ocr` 引数と警告表示。
